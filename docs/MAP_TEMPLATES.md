# Procedural reference templates

`UERMapTemplate` supplies a reusable, data-driven arena to `AERProceduralMap`.
Without TemplateAsset the existing room/corridor laboratory generator is used.
The playable Killhouse template is `/Game/EclipseRecoil/Art/MapTemplates/DA_Killhouse`
in `/Game/EclipseRecoil/Maps/L_Killhouse`. Select **Killhouse procedurale** for
local or LAN play. `ERMapGenerate 7919 8 1` changes its seed; the retained room
count argument is ignored by arena templates. Only one arena floor is supported.
`?MapSeed=7919` also works at level travel. New Killhouse sessions started from
the menu choose a fresh seed; direct level travel without a seed retains42 for
reproducible authoring/tests. `-ERBlockDebug` shows diagnostics.

## Reference and revised layout

Workshop526448928 contained `de_killhouse.bsp` (BSP21):1,584 brushes,95 static
props,47 BSP models and ten spawn entities per team. The original read-only
Source converter measures X -816..816 / Y -1551..1552 Source units, approximately
41.45x78.82m. Area-weighted surface analysis, prop inventory and source hashes
are private in maps SourceAssets/MapTemplates. No Valve meshes/textures imported.

Revision3 varies arena width36..48m and length70..90m independently, in50cm
increments. The original41x79m footprint remains the reference assembly. Each
variant has two bases near its spawn bands. Ground-floor access is
at the rear; the field-facing wall has firing windows. Each base contains an
internal stair with rise<=20cm, a220cm-wide opening in the roof, a solid walkable
roof and100cm parapets. Base width10..14m, depth8.5..10.5m, position and wall
height2.5..3m vary as a complete assembly. Rails protect the stairwell sides; the
upper stair exit remains open. This matches the user's reference screenshot and
replaces the first prototype's front-door, inaccessible-roof arrangement.

The `Variation` recipe selects4..6 paired battle modules (8..12 total), with
sampled widths, depths, heights, counts and arrangement. Seven module families:
through rooms, L/U cover, staggered walls, cargo clusters, tanks/barrels and
wooden stacks. L/U cover can be fixed industrial panels or destructible project
blocks. At least one room pair is included when Room is enabled. Each room has
two160cm-wide standing doorways and side firing windows; the doors can shift
inside the room. The central watch platform changes dimensions/height and keeps
stairs from both ends.

Modules occupy disjoint cells. A reserved outer loop, end crossovers and gaps
between rows connect the arena. No retry-dependent obstacle scattering: one
random stream samples a complete half, then generation emits its matching copy.
Native validation rejects overlaps, out-of-bounds volumes, obstructed starts,
complete patrol segments and room access paths before replacing the live map.
The older authored group-offset mode remains available with Variation disabled.

## Balance by construction

New playable templates default to HalfTurn symmetry. Author one member of each
pair with Mirrored=true; generation emits its `(X,Y,Z)->(-X,-Y,Z)` counterpart
with the same size, material and relative damage-cell arrangement. Random offsets
are sampled once, then transformed with the pair. Symmetry therefore holds for
every seed rather than relying on independent random choices for each team.
Unmirrored pieces in this mode must have XY centre0 and no jitter; use them for
invariant central slabs. Legacy None remains an explicit compatibility mode,
not the default for playable reference templates.

In revision3 Alpha starts form two clear rows behind the sampled base.
Omega is generated by the same half turn, including facing. The original Alpha
measurements remain in the reference assembly for authored mode. This deliberately
normalizes the unequal distances in the original spawn bands: the user's later
balance requirement supersedes the first prototype's exact20-source-spawn rule.
All20 spawns use Z100cm for the185cm Respawn & Rage capsule. Walls, fixed cover, routes and
stairs have matching geometry on both sides. Cosmetic team identification may
still differ. The older procedural laboratories remain test fixtures.

## Industrial art and destruction

Selected FactoryEnvironmentCollect static meshes and their dependencies live in
the private maps mount at `Art/FactoryEnvironment`. Their original materials
remain on fixed shell panels, shed roof panels, beams, columns, guard panels,
cargo containers, tanks and barrels. The concrete foundation retains
the existing project surface.

Destructible bases/parapets/low walls use the existing project Concrete profile;
wooden stacks use Wood. `DA_ER_BlockMaterials` and its materials/combat settings
are unchanged. Vendor meshes are rejected on destructible pieces. Roof parapets
have an explicit base-course anchor to their fixed roof slab; upper courses keep
the shared support/damage behavior.

Walkable base roofs, watch decks and all stair treads use solid project cube
geometry with the existing Metal surface. The visible geometry is the collision
geometry. Detailed Factory platform/grill meshes have holes, frames and raised
details; fitting them to arbitrary slab boxes caused the reported visual gaps
and protrusions. `WalkableSurface` rejects any fitted FixedMesh (and destructible
slabs), preventing that substitution from recurring. Only the intended stairwell
remains open. The retained authored assembly receives the same surface fix.

Other FixedMesh art is fitted using its actual bounds and MeshRotation. Visible industrial
ISMs are query-free; hidden authored box volumes provide coherent static cover,
steps and platforms. This preserves clearances and avoids decorative mesh holes
changing server/client collision. The proxy is a box approximation, not exact
per-triangle vendor collision. Fixed art remains indestructible. Map loading
never re-enables collision on the tagged visual ISMs. Roof art has its own tag
so the probe can make an overhead cutaway without hiding other fixed geometry.
Roof tiles span the arena plus the 20cm shell walls (Size+40, like the collision
ceiling). A roof that only meets the wall tops along an edge leaks a line of
sunlight through the shadow map onto the floor (18 October Metal captures).

The protocol6 descriptor includes the selected template asset. Layout digest
includes template identity/revision/symmetry, logical records, fixed volumes,
mesh path/collision GUID, mesh rotation, roof flags, sampled arena dimensions, circulation and spawn transforms.
Peers validate the descriptor and complete snapshot before enabling collision.
Late joins, damage and seed epochs reuse the existing server-authoritative path.

## Rebuilding

1. `analyze_source_template.py` reads a BSP or one-BSP Workshop ZIP using the
   existing converter; output measurements/provenance privately.
2. `build_killhouse_manifest.py` authors the balanced revision2 assembly JSON.
   This is construction input, not a runtime file dependency.
3. `migrate_factory_assets.py -ERFactoryPhase=stage` runs inside the supplied
   Factory project with Python enabled. `rehome` runs in the resulting isolated
   Saved/FactoryMigration-* project. Unreal renames/saves the selected package
   closure into the private Art namespace before migration to Respawn & Rage. Source packages
   are not saved. Selection/inspection/receipts stay private.
4. Compile the Editor module. `setup_killhouse_template.py` creates only absent
   assets/maps. `setup_killhouse_factory.py` upgrades the earlier prototype once;
   native validation covers103 distinct seeds before save, and the destruction catalog's
   SHA256 must remain unchanged. A completed manifest/revision marker preserves
   later artist edits. Use an explicit new revision for further layout changes.

5. `setup_killhouse_variations.py` applies the explicit revision3 migration. A
   detached candidate validates516 seeds before save. The private variation
   recipe and its hash have their own marker; subsequent edits are preserved on
   rerun. This migration changes only DA_Killhouse, with map/catalog SHA checks.
   `Variation` contains the ranges, module choices and Factory mesh palette;
   runtime generation does not read JSON or external project files.

Edit or duplicate assets through Unreal to add other balanced templates. Keep
licensed assets and their dependency closure in the private maps submodule.

## Climbing narrow roof parapets

The base parapets are100cm above the roof and20cm thick. Space+forward uses the
existing assisted climb (limit150cm); the ordinary ballistic jump remains about
60cm. Ledge detection samples just inside the contacted face, follows a bounded
continuous top interval and places a narrow-edge landing inside its supported
strip. Broad obstacles retain their previous landing distance. Full standing
clearance, input requirements, swept traversal and saved-move replication remain
in force; no jump-height increase or map/asset edit is required.

MapTemplate automation checks all four parapets on both bases for six seeds.
`test-parapets.py` exercises16 real input cases: eight host climbs and eight
autonomous client climbs, with server verification of top support and traversal.
Optional `--render` captures the first mounted position.

## Dust town revision3 — reference-plan streets and courtyards

The user's later plan and wooden-door photograph supersede the first Dust
arena's HalfTurn layout and fixed topology. Killhouse remains unchanged.
Dust now uses a separate serialized `Town` recipe with seven named streets:
Mid, B_Tunnels, B_CT, CT_A, A_Long, Long_Approach and elevated Short_A. Six
courtyards keep the supplied plan's approximate arrangement: T south, CT north,
B west, A east, plus the long approach court and tunnel hall. This is a semantic
adaptation of the plan, rather than a contour-exact Source2 reconstruction.
The reference images and recipe remain in private SourceAssets/MapTemplates/DustTown.

Seeds sample arena dimensions76..86x84..96m, shared piecewise plan-axis warps,
street widths, door slots and building heights4.5..8m. The complement of the
carved street/court union is partitioned into whole solid building parcels.
Consequently entire facades, bends, junction spacing and courtyard proportions
change with the seed. Court/route relationships remain stable. Material and
geometry budgets are explicit: max100 parcels,80 exposed window panels,1024
generated pieces and2048 final fixed instances. Near-coincident parcel slivers
below2cm are omitted; they cannot form a character passage. All other templates
retain the original256 authored-piece limit.

Short_A is an embankment/catwalk route at320cm with two ordinary20cm-rise stair
approaches. It bridges CT_A with290cm clear space underneath. Both ordinary
and elevated routes derive their tests and probes from generated metadata.
The surrounding buildings close the old arena's open sight lines, form alleys
and delimit courts. Closed windows/shutters face actual open lanes. Roof slabs
and treads have matching solid render/collision volumes.

Three gateways (B tunnels, Mid and the long approach) have owned curved arch
surrounds and two inward-open curved timber leaves, with dark cross braces.
Leaf angles vary20..30degrees and the standing slot110..130cm. Their collision
planks rotate with the wood; planar SAT rejects solid overlaps without treating
tilted neighbouring plank AABBs as actual intersections. Upper arch collision
uses24 authored strips; the curve remains an approximation. Cosmetic art has
no query collision and cannot close the standing passage. The OBJ sources are
project-authored, explicitly triangulated with UVs and hard face normals and
imported through Unreal. Fixed town timber uses a warm, vertically oriented
copy of the existing project PBR wood, with matching transposed normal basis.
The shared destruction catalog and its gameplay settings remain unchanged.

`build_dust_town_recipe.py` writes construction data and owned OBJ sources.
`setup_dust_town.py` imports them and applies the explicit revision3 migration
only after515 seeds validate, then updates the existing map's paving and
patrol actors for the complete circuit. The completion hash is saved last.
`setup_dust_town_art.py` is a separate one-time art migration. Repeated completed
setup preserves later artist edits. Template palette references are saved in
the private data asset; runtime never reads the source JSON or external project.

Town surfaces, physical leaf rotations, street/stair routes, crossing metadata
and door dimensions contribute to the geometry digest. Initial peers, late
joins, damage and seed epochs retain the existing server-authoritative snapshot
gate. `DustTemplate` covers512 layouts and six physical cases;
`test-dust-template.py --render --network` walks all three gates, the CT
underpass and the complete bent Short_A to A, then checks real shots, damage,

`setup_dust_town_projection.py` repairs the four owned town PBR copies once.

### Dust town revision4 — compact plan and opposite-swing gates

The latest user request reduces the sampled arena to66..75x73..84m, about13%
smaller on each axis (about24% less area at range midpoints). The plan graph,
street-width ranges, player scale, stair rise and crossing clearances remain
unchanged. The same axis warps still reshape entire parcels and courts.

One timber leaf swings inward, the other outward. Both leaf planes have the
same rotation, with their free edges overlapping24cm in frontal projection.
The angle derives from portal width and the sampled110..130cm diagonal gap;
wood/brace thickness has a clearance allowance. Standing passage follows a
six-point dogleg. Straight frontal movement and frontal sight rays at standing
height are blocked in both directions. These are static half-open gates.

Generated street and closed patrol routes insert the dogleg in travel order,
reversing it for opposite travel. Gate metadata owns the actual passage, and
its vertices contribute to the geometry digest and memory accounting.
Route/spawn validation transforms the capsule envelope into each solid's
unscaled local frame, retaining conservative35cm/93cm safety margins without
falsely closing the rotated passage through world AABBs.
Town patrol actors use10cm waypoint acceptance; other maps retain90cm.

`setup_dust_town_compact.py` is the explicit revision4 migration. It copies
the existing town palette, validates515 candidate seeds, updates the sampled
plan bounds and saves42 patrol actors. Its completion hash preserves later
artist edits. The map/template change is private; Killhouse and the shared
destruction catalog are protected by byte hashes. No source mesh or material
changes are needed for the opposite swings.

DustTemplate checks512 compact plans and six physical seeds, every dogleg in
both directions and nine frontal sight rays per gate from each side. The
actual rendered/LAN probe walks the doglegs before testing both crossing
levels, combat, seed replacement and initial/late snapshots.
